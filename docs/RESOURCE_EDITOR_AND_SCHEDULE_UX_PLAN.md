# 作息时间与资料编辑稳定性改造方案

> 状态：v1.0 已批准，等待功能实现与验证结果回填。

## 1. 原始问题与目标

本轮解决四组彼此关联的问题：学校作息时间在移动端和电脑端都难以编辑；资料编辑页反复清空加载；资料上传限制与错误信息不可理解；OCR 页面底图失败，表格、图片、公式和 PaddleOCR 块类型在保存后丢失。

目标是让教师在手机和电脑上都能稳定完成作息设置、资料上传、资料重访和 OCR 阅读，并保证 OCR 的原始类型、坐标、纯文本和展示内容可追溯、可恢复，不能再把结构化识别结果压成普通文本。

## 2. 已确认事实、假设与未决问题

### 2.1 已确认事实

1. 作息设置使用原生 `input[type=time]`，电脑端会出现分段编辑时、分的交互；移动端控件尺寸低于 44px，且开始、结束只有无障碍标签，没有可见字段标签。
2. `KnowledgeLibrary` 离开页面后会卸载；重新进入时请求资料列表、完整知识图谱和资料详情，并通过父组件再次请求知识图谱。
3. 资料解析中每 1.8 秒同时刷新详情、资料列表和完整知识图谱。生产请求本身通常只需数毫秒，等待感主要来自前端状态清空、重复请求和重复渲染。
4. 资料上传的服务器限制为 80 MiB，界面却显示“PDF 最大 500 MB”，上传前没有文件大小校验，前端会把 `HTTP_413` 等技术码直接展示给教师。
5. PaddleOCR 已返回 `header`、`text`、`image`、`paragraph_title`、`table`、`footer`、`number` 等原始块类型，并返回页面尺寸、坐标、Markdown、页面源图和内容图片。
6. 当前规范化阶段只区分少量类型，`image` 等类型会退化为 `paragraph`；写入 `resource_chunks` 时又丢弃块类型和 Markdown，只保留文本及坐标。
7. 当前 OCR 公式展示仅识别单个 `$...$` 行内公式；HTML 表格会显示成 `<td>` 字符，内容图片没有进入详情展示模型。
8. PaddleOCR 页面源图已经下载，且像素尺寸与 OCR 坐标系完全一致。但当前 SDK 调用把目录作为保存目标，所传 `filename` 不生效，文件落为远端 basename，例如 `input_img_0.jpg`。
9. OCR 底图接口没有使用已下载的页面源图；缓存缺失时转而调用生产环境中不存在的 `pdftoppm`，因此接口返回 400。

### 2.2 假设

- 第一阶段资料类型仍以 PDF 为主，现有 80 MiB 上限保持不变。
- OCR 富内容预览以“忠实展示识别结果”为目标，不允许执行 PaddleOCR 返回的任意 HTML。
- 资料工作区缓存只在当前登录会话内有效；退出登录必须清空。

### 2.3 未决问题

- 个别历史解析页可能没有可恢复的页面源图。迁移时只根据真实文件和尺寸校验归位；无法确认的页面标记为需要重新解析，不生成伪底图。

## 3. 是否需要修改代码

需要。问题同时位于输入控件、前端数据生命周期、上传错误契约、OCR 规范化模型、SQLite 结构、解析资源落盘和页面图片接口，单纯调整文字或 CSS 无法解决。

## 4. 推荐最短路径与备选方案

### 4.1 推荐路径

1. 用统一的完整时间输入替换原生分段时间控件：支持输入或粘贴 `08:00`，手机输入 `0800` 自动规范化，控件至少 44px 高。
2. 把资料目录、图谱和当前详情提升为登录期间的工作区状态；有缓存时立即显示并后台刷新，解析轮询只读取当前详情，状态结束后再刷新目录与图谱。
3. 建立前后端共享的 80 MiB 上传策略；客户端上传前拦截，服务端错误统一翻译成教师可理解的原因和下一步。
4. 扩展 OCR 内容模型和 SQLite：永久保留 PaddleOCR 原始块标签、应用规范类型、纯文本、Markdown/展示内容、坐标和内容资源引用。原始块标签不能被覆盖或丢弃。
5. 把 PaddleOCR 页面源图直接写入唯一规范路径 `page-images/page-N.jpg`；OCR 阅读器只读取这份与坐标一致的底图，删除运行时 `pdftoppm` 隐式兜底。
6. 使用受限的 React 结构渲染表格、图片和公式；不直接执行原始 HTML。表格仅接受允许的表格元素，图片仅使用当前用户工作区内的受保护 URL。
7. 在产品数据快照副本上演练 SQLite 迁移和已有页面图归位，通过后才部署到权威数据。

### 4.2 放弃的备选方案

- 继续使用浏览器原生时间输入：实现最省，但无法解决电脑端分段编辑和跨浏览器不一致。
- 只把 `<td>` 通过 `dangerouslySetInnerHTML` 显示：改动小，但会丢失块类型、图片关系并扩大不可信 HTML 风险。
- 给生产环境安装 Poppler 作为 OCR 底图兜底：可以绕过当前 400，但仍会忽略 PaddleOCR 已提供且与坐标严格一致的页面源图，并保留两条互相漂移的底图链路。
- 只延长缓存时间或加全屏骨架屏：会掩盖重复请求，不解决组件卸载和轮询放大的根因。

## 5. 修改文件与范围

### 前端

- `src/features/settings/SystemSettingsPanel.tsx`：作息卡片布局、可见标签、时间校验和移动端尺寸。
- 新增统一时间输入组件及测试。
- `src/App.tsx`、`src/features/knowledge/KnowledgeLibrary.tsx`：资料工作区状态生命周期、缓存、请求去重和轮询收敛。
- `src/features/knowledge/ResourceLibraryEditor.tsx`：上传提示、中文错误、底图失败状态、按类型渲染 OCR 表格/图片/公式。
- `src/services/resourceApi.ts`：上传策略及结构化错误映射。
- `src/domain/types.ts`：OCR 块的原始类型、规范类型和展示字段。

### 服务端与数据

- `server/config/runtimeConfig.ts` 及共享上传策略：消除 80 MiB/500 MB 双重口径。
- `server/services/materials/PaddleVisionMaterialParser.ts`：保留 PaddleOCR 类型，保存确定文件名的页面源图和内容图片。
- `server/services/resources/resourceAnalyzer.ts`：检索纯文本与展示内容分离，构建带类型的 chunk。
- `server/services/resources/resourcePageRenderService.ts`：改为读取唯一规范页面源图，移除 OCR 路径的 `pdftoppm` 运行时兜底。
- `server/repositories/resourceRepository.ts`、`server/database/resourceMigrations.ts`：新增字段及兼容迁移。
- `server/routes/resources.ts`：受保护的页面图和内容图片响应、稳定错误码。
- 新增迁移/回填脚本和相应测试；脚本先支持只读预检，再在已验证快照上执行。

## 6. 风险、取舍和验证方式

### 风险与控制

- SQLite 结构和文件路径迁移：部署前必须制作 SQLite 在线备份及完整文件快照，并在副本上先演练、校验、回滚。
- OCR HTML 属于外部输入：不直接注入 DOM，只解析允许结构；纯文本继续作为检索和 AI 分析输入。
- 登录期间缓存可能陈旧：所有写操作精确失效相关资源，后台刷新不清空当前内容，退出登录清空全部缓存。
- 历史页面资源不完整：只归位可验证文件，其余明确要求重新解析。

### 验证

1. 在 390×844、768px 和 1440×900 验证时间输入、触控尺寸、无横向溢出和键盘可用性。
2. 输入 `0800`、`8:00`、粘贴 `08:00` 均得到稳定值；非法时间和结束早于开始有中文提示。
3. 重复进入资料编辑不清空已有内容，完整知识图谱不重复拉取；解析轮询只查询当前资料。
4. 超过 80 MiB 的测试文件在请求发出前被拦截，界面显示实际大小、上限和处理建议；服务端 413、401、403、429、502/503/504 都有中文提示。
5. PaddleOCR 原始块类型在 API、SQLite 和重新加载后保持不变；表格不出现裸 `<td>`，图片走受保护地址，行内及独立公式可显示。
6. 页面底图接口返回 200 和正确图片类型，图片尺寸与 OCR 页面尺寸一致，识别框坐标对齐。
7. 在产品快照副本执行迁移后检查文件清单、哈希、SQLite `integrity_check`、记录数量和跨用户隔离；执行回滚演练。
8. 运行 TypeScript、生产构建、资源/认证/工作区隔离测试及真实浏览器桌面和移动端烟雾测试。

## 7. 本阶段不做

- 不改变 80 MiB 上限。
- 不引入对象存储、微服务或独立 OCR 服务。
- 不允许 OCR 原始 HTML 任意执行。
- 不重做知识图谱产品结构。
- 不自动删除原 PDF、原解析产物或历史备份。
