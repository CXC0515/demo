# 空工作区与班级字段修正方案

> 文档版本：`v1.0`
> 日期：2026-09-09
> 状态：代码与隔离环境验证已完成，待合并和生产升级审批
> Git 基线：`origin/main@52fdf13349e83264377e437fa6b74bf6defb490d`

## 1. 原始问题与目标

受邀教师在全新空工作区中遇到三个直接阻断试用的问题：打开“学情诊断”白屏、“班级可视化”没有内容、创建班级失败。同时，班级基础资料里出现了没有必要的班级级“任课教师”字段。

本次目标是让没有任何业务数据的新教师能够从空工作区完成“看懂当前状态 → 创建班级 → 进入学情诊断和班级可视化”的最小闭环，并彻底删除班级级“任课教师”字段，不保留空字段或兼容占位。

## 2. 已确认事实、决策与边界

- 新教师工作区确实为独立空工作区，未复制管理员测试数据；问题来自页面对空数组的处理，不是数据隔离失效。
- 学情诊断曾直接读取不存在班级的名称；班级可视化在没有班级时直接返回空页面。
- 创建班级 API 曾强制要求 `chineseTeacher`，前端又默认填入“王老师”，因此新用户会遇到失败或垃圾数据。
- 邀请备注名保留，注册人仍可在注册时填写自己的姓名；本次不修改邀请、角色和管理员权限。
- 班级资料只保留“班主任”。课表中每节课程的 `teacherName` 是另一业务概念，继续保留。
- 不触碰公网运行目录 `/Users/cxc/Projects/DEMO/var-product`；合并和生产升级须另行批准。

## 3. 最短实现路径

1. 在前端领域类型、班级 API 校验、repository 写入和旧 JSON 导入中删除 `chineseTeacher`。
2. 增加 SQLite 第 11 版迁移，用 `ALTER TABLE classes DROP COLUMN chinese_teacher` 删除旧列。
3. 学情诊断与班级可视化在无班级时显示明确空状态和“创建班级”入口，不再白屏或返回空 DOM。
4. 学情诊断删除硬编码教师、班级、学生和 AI 建议，只展示当前工作区真实学生数据；没有真实证据时明确提示。
5. 创建/编辑班级等待 API 成功后才关闭弹窗；失败时保留输入并显示错误。
6. 同一响应式页面覆盖手机、平板和桌面，不建立单独移动端。

备选方案是只把 `chineseTeacher` 改成可选并隐藏输入，但这会永久留下无业务意义的数据库列和兼容分支，未采用。

## 5. 数据迁移、校验与回滚

生产升级前必须先停止应用的新写入，并对当前 `var-product` 创建一次明确命名的升级前产品快照。SQLite 必须走项目的在线备份脚本，上传资料和解析产物纳入同一文件清单与 SHA-256 校验；不能直接复制正在运行的 `.sqlite`、`-wal`、`-shm`。

先把快照恢复到全新的临时目录，以待合并代码启动并执行第 11 版迁移。验收项包括：全部 SQLite `integrity_check=ok`、旧班级数量与内容不变、`classes.chinese_teacher` 不存在、班级读写成功、资料引用与文件哈希无缺失。

只有副本演练通过后才升级生产。若迁移或页面验收失败：立即停止新版本，保留故障目录和日志，切回升级前代码与升级前快照恢复出的新目录；不覆盖故障目录，也不自动合并升级后的新增写入。

这是一份升级前人工恢复点，不属于每日自动轮换目录，不会每天制造重复垃圾数据；是否删除需要另行列出大小和替代恢复点并获得授权。

## 6. 风险与取舍

- 删除列是不可逆 schema 变化，所以生产前必须完成在线快照、恢复演练和旧班级抽查。
- SQLite 版本需支持 `DROP COLUMN`；当前开发与生产 Node 原生依赖组合支持，迁移测试已覆盖旧 v10 数据库。
- 空状态解决的是“可理解、可继续操作”，不虚构诊断结果；这会让无真实批改数据的页面内容较少，但符合数据可信边界。
- 班级保存失败现在保留弹窗和输入；错误提示仍是通用文案，具体技术原因继续通过服务端结构化日志追踪。

## 7. 验收结果

- TypeScript 检查、生产构建和完整 100 项自动化测试通过。
- roster 7 项、classroom 4 项、schedule 11 项、auth 1 项、workspace isolation 2 项测试通过。
- SQLite v10 → v11 测试确认旧班级保留、旧列删除、`user_version=11`。
- 隔离临时数据根完成真实浏览器注册与登录；新用户没有管理员测试数据。
- 390×844 手机视口确认新建班级弹窗无“任课教师”字段，输入控件和操作按钮可用。
- 创建班级成功后弹窗关闭并自动选中新班级；无学生时学情诊断显示真实空状态。
- 无班级时学情诊断和班级可视化均有创建入口；有空班级时可视化正常渲染座位图。
- 浏览器交互期间没有新增运行时错误；注册页出现的未登录 401 和缺少 favicon 404 为既有非阻断请求。

## 8. 本次明确不做

- 不修改邀请名称、教师注册姓名和 owner-only 邀请权限。
- 不删除课表的课程级“任课教师”。
- 不给空工作区复制管理员演示数据。
- 不生成虚构学情、虚构 AI 建议或默认教师姓名。
- 不在本分支触碰真实生产数据、重启公网服务、推送、创建 PR 或合并。
