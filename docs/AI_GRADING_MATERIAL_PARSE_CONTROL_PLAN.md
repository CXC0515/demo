# AI 批改材料解析控制与拆题失败修正

> 文档版本：`v1.4`
> 日期：2026-09-13
> 状态：v1.0 已通过 PR #20 合并部署；v1.1 通过 PR #21 交付；v1.2、v1.3、v1.4 已本地实施，等待用户验收
> 开发基线：本地稳定 `main@fe27241127622d6fa74e7c5d1a40d519b06f7a71`

## 1. 原始问题与目标

教师选择作业题目或参考答案后，页面会立即上传并开始材料解析，没有核对文件和主动开始的控制点。一次选择多份文件时，教师无法在资源消耗前纠正选择。

同时，生产环境显示“AI 拆题失败，请检查模型配置”，但 2026-09-12 的真实日志表明实际错误是上游模型服务返回 HTTP 503。目标是恢复教师对解析时机的控制，并让拆题失败反馈准确说明失败阶段、数据保存状态和下一步操作。

## 2. 已确认事实

- 题目和答案文件输入此前直接调用上传接口；服务端收到文件后在后台异步、并行解析，前端轮询材料状态。
- 单次材料上传最多 20 个文件、每个文件最多 4 MiB。本次不降低数量，也不把解析改成串行。
- 故障任务只有 1 份题目和 1 份答案；两份材料均为 ready、无解析警告，共 27 个内容块和约 1453 个字符。
- 19:16 左右四次拆题请求均记录 `MODEL_REQUEST_FAILED:503`。第一次约 70.6 秒后失败，随后三次约 0.5–1.3 秒内失败。
- 前端未识别该错误码，落入“请检查模型配置”的默认文案；材料和模型配置不是本次已知根因。
- 日志没有记录上游响应正文，因此只能确认服务暂时不可用，不能把排队、维护或网关过载中的任一项断言为事实。

## 3. 产品与实现决策

1. 文件选择只进入浏览器待解析区，不自动上传或解析。
2. 题目和答案共用一个“上传并开始解析”主操作；点击后仍按现有机制并行上传、后台异步解析和轮询状态。
3. 待解析区显示文件数量、文件名、清除入口和替换影响；重新解析对应材料会使已有拆题结果失效。
4. Compact 下主按钮占满可用宽度，Wide 下保持紧凑；主要操作和清除入口高度不低于 44px，调整窗口不丢失待处理文件和错误状态。
5. AI 拆题按钮只在题目、答案均已解析时可用。
6. 服务端把上游 401/403、429、502/503/504、其他拒绝和输出结构错误映射为不同稳定错误码。
7. 页面保留持久失败卡片和重新拆题入口；失败时明确材料已保存、本次未生成拆题结果。
8. 本次不自动重试模型请求，避免外部服务不可用时连续产生无意义调用。

## 4. 修改范围

- `src/features/grading/GradingWorkflow.tsx`：待解析文件状态、统一开始按钮、响应式布局、拆题可用条件及持久错误反馈。
- `server/routes/gradingTasks.ts`：拆题模型错误分类与 HTTP 状态语义。
- `docs/PROJECT_HANDOFF.md`：校正 PR #19 稳定基线。
- `docs/WEB_PRODUCT_PHASE1_PLAN.md`、`docs/EMPTY_WORKSPACE_CLASS_FIX_PLAN.md`：校正 PR #11 和生产 schema v11 的实际状态。
- 本文：记录问题、证据、决策、范围和交付状态。

## 5. 风险与取舍

- 文件在点击开始前只存在于当前浏览器选择状态，刷新页面后需要重新选择；这是避免未经确认上传和解析的直接取舍。
- 并行解析保留现有效率，也保留单次多文件对本机和 OCR 服务的瞬时压力；当前最多 20 个文件且用户明确接受该边界。
- 上游 503 无法由本地代码消除。本次修正可观察性和恢复入口，不把外部服务故障伪装成已经解决。
- 新材料仍会替换同类型旧材料并使旧拆题结果失效；页面在执行前明确告知，不改变现有数据语义。

## 6. 检查与授权边界

按用户要求只执行代码审查、TypeScript 静态检查、部署所需生产构建和 `git diff --check`；不调用真实 OCR/AI，不执行完整测试矩阵或浏览器验收。网站体验由用户在合并部署后验证。

v1.0 实施当时只授权本地提交，后续经用户单独授权后通过 PR #20 合并并从母文件夹稳定 `main` 部署；COS TODO 补记已一并纳入。

## 7. v1.1 真实拆题失败根因

PR #20 部署后，用户在正式网站两次触发拆题。请求均到达正式服务，分别约 63 秒和 74 秒后返回 502。模型已返回可解析 JSON，但第 2 题的 `knowledgeCandidates` 是字符串数组，而服务端契约要求 `{ nodeId, nodeName, confidence }` 对象数组，整份输出因此在业务收敛前被拒绝。

因果链为：

1. Prompt 只展示了空的 `knowledgeCandidates: []`，没有非空对象示例。
2. 拆题请求未使用项目已有的 `response_format/json_schema/strict` 机制，只依赖自然语言提示。
3. 服务端在可恢复的知识点字段被处理之前就严格解析整份结果，一个次要字段错误放大为整份拆题失败。
4. 正式环境使用第三方 OpenAI 兼容网关；其对当前模型严格 JSON Schema 的完整支持仍需由用户的真实网站验收确认。

## 8. v1.1 实施决策

1. 拆题请求复用 `firstSectionAnalysisJsonSchema`，启用 `response_format: json_schema` 和 `strict: true`。
2. Prompt 增加非空知识点对象示例，明确禁止字符串数组。
3. 仅对 `knowledgeCandidates` 执行允许列表式恢复：移除非法候选项，并向对应题目写入人工复核原因；不猜测节点、不伪造置信度。
4. 题干、答案、题号、分值和证据引用等核心字段仍严格校验；异常时不入库。
5. 记录恢复的题号和候选数量，不记录完整题目、答案或模型原始输出。
6. 不增加自动重试；兼容网关若拒绝严格 Schema，保留失败并继续显示可操作错误，不二次计费。

## 11. v1.2 根因与决策

真实答案 OCR 中一个 block 可能同时包含多道题。旧契约要求 `standardAnswer` 逐字复制整个来源 block，服务端又用 block 全文覆盖模型返回内容，导致模型即使理解题目边界，也无法表达“同一 block 中只属于本题的片段”。第 4、5 题还出现了完全相同的错误来源，严格 JSON Schema 只能保证结构合法，不能保证语义对应。

本版不使用阿拉伯数字或其他固定题号正则切分材料。题目和答案的全部 OCR、完整连续文本、block 顺序与 ID 仍在一次请求中交给 AI；每个来源新增 `segments`，逐项记录真实 `blockId` 和该 block 中逐字存在的本题 `quote`。服务端验证引用存在、文本与片段一致以及异常重复关系，不再用物理 block 全文覆盖每题答案。第一次输出不一致时最多进行一次整份纠正调用；仍不可靠的答案不写入评分依据，转为教师确认。

PaddleOCR 将原始页面保存于 `page-images/page-N.jpg`，旧裁剪和质检入口却读取 `resources/page-N.jpg`。本版统一页面路径，补齐受保护的完整原页接口，并让缺少页面文件与模型服务失败使用不同错误反馈。没有重新解析或迁移现有材料。

上传质检增加管理模式：Wide 使用表格复选框，Compact 使用可勾选卡片；全选仅作用于当前筛选列表。删除必须经过选择和确认弹窗两步，弹窗列出文件与影响范围。只删除明确 asset ID 对应的应用副本、解析产物、质检和批改结果；题目、答案、评分细则、其他答卷及教师电脑原文件保持不变。处理中的答卷禁止删除，避免异步任务写回。

## 12. v1.2 检查与未决项

- 只运行 TypeScript、AI 拆题、上传质检、试批和名册匹配的针对性检查，不调用真实 AI/OCR，不修改 `var-product`。
- 当前母文件夹的交接与运维文档包含用户尚未提交的备案下线状态，本专项不从旧基线覆盖；待用户验收并授权 Git 收尾时，再在母文件夹合并最新状态。
- 用户需在本机用真实题目、答案和答卷确认模型片段对应质量、来源图片加载、多选范围及二次确认删除体验。

## 13. v1.3 答案完整性、母题结构与公式渲染

真实样本确认第 3(2)、4、5 题答案存在于 OCR，但模型返回的引用因空格、全半角括号、标点或排版差异未通过逐字 `includes` 校验，服务端随后清空答案，形成假缺失。答案 OCR 的 block 粒度也可能覆盖多道题，因此“语义对应正确”和“字符引用完全一致”不能继续作为同一字段约束。

本版保留整份 OCR 一次交给 AI，不引入固定题号正则。`stem` 与 `standardAnswer` 用于教师阅读，来源 `quote/segments` 保留 OCR 原文；来源依次执行精确匹配、仅忽略 Unicode/空格/标点差异的规范化匹配，仍无法精确定位时保留答案和整个 OCR block，明确标记为待教师确认，不再伪装成答案缺失。重复答案来源继续告警但不静默删除。

产品术语统一为“母题/小题”。母题只显示公共材料和公共要求，已进入 `subquestions` 的小题题干不再在母题中重复。题干中的 `$...$`、`$$...$$`、`\\(...\\)` 和 `\\[...\\]` 使用 KaTeX 渲染，原始 OCR/LaTeX 仍可在证据区查看，不通过删除标识符换取表面整洁。

拆题接口保存 `startedAt`、`completedAt` 和 `durationMs`。完成态在 Compact、Medium 和 Wide 下持续显示母题数、小题数和真实耗时；历史结果没有该字段时不估算、不伪造。按用户授权不调用真实 AI/OCR，只进行定向代码检查，真实材料由用户在本机验收。

## 14. v1.4 题目正文、知识点与答卷重试闭环

题目正文优先从题目 OCR 来源中恢复，再按小题的来源片段和完整题干做精确去重；不依赖罗马数字、阿拉伯数字或题号正则。教师手动修正过的题干具有最高优先级。用户界面统一使用“题目”“第 N 题”等中性称呼。

知识点按钮改为可逆状态：再次点击已关联项即可取消，并把选择结果保存到本次拆题结果中。Compact 与 Wide 均保留至少 44px 的触控高度和明确选中反馈。

学生答卷上传成功后立即清空浏览器待上传队列。OCR 失败时，页面等待本批次全部文件进入终态并回读服务端状态；失败项通过原 asset ID 原地重试，不再次上传文件。管理模式只禁止选择真正处于上传或识别中的记录，其余成功、待复核和失败记录均可全选，并继续执行二次确认删除。现有重复记录不按文件名自动删除。
