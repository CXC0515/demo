## 1. 本版概要

本版记录第 2 切片的实际实施结果及首次本地验收修正：邀请注册和登录明确拆分，注册阶段不创建会话，注册成功后返回登录页；教师资料采用注册时实际填写的姓名。首个所有者继续读取迁移候选数据，后续受邀教师只获得全新空工作区。公网 Tunnel、域名 DNS、自动开机和国内三网实测尚未实施，因此仍不能邀请外部用户。

本版确认用户已经取得长期使用的 `unreached.cn`，并仅把一个月阿里云万小智 AI 建站权益视为临时赠送能力。默认部署路径仍为：

```text
受邀教师浏览器
        │ HTTPS、自有域名、同源 Cookie
        ▼
Cloudflare 全球网络与 Tunnel（免费起步）
        │ 由 MacBook 主动建立出站连接，无需公网 IP
        ▼
24 小时运行的 MacBook
        ├── 单实例 Node/Express
        ├── Vite 构建产物与受保护 API/文件
        ├── Better Auth 注册、登录、会话与邀请
        ├── 每位教师独立工作区
        ├── SQLite、上传资料、OCR/解析产物
        └── 本地 Python、PDF 工具与远程 OCR/AI
```

第一阶段不购买服务器。服务器仅在中国电信、联通、移动真实测试不达标，或备案/运营要求明确需要中国大陆云资源时，作为另行审批的备选方案。

主要成本是域名/建站权益续费、MacBook 电费、已有 AI/OCR 调用费和可选的备份介质。Cloudflare Tunnel 免费起步。Agent Mail CLI 先用于人工发送少量邀请邮件；它能否承担自动邮箱验证和密码重置，要经过第 6.4 节的能力验证。

一个月共享 ECS/建站权益不进入关键依赖：产品在它到期、停用或配额耗尽后仍必须正常运行。它最多用于备案、临时说明页或虚构数据技术验证。官方资料证明它能构建并安装带 Dockerfile 的 `.tar` 应用，却没有证明轻量共享实例提供独立 SSH、稳定持久卷、长任务进程保障和可恢复备份。不得把母文件夹真实数据直接上传试错。

## 2. 原始问题、目标与边界

### 2.1 原始问题

当前 DEMO 是本地教师工作台。功能已经覆盖班级、学生、课表、日程、资料、OCR、知识结构和批改，但不能安全地直接暴露到互联网：没有登录和用户隔离，资料路径部分公开，生产入口尚未同源托管前端，长任务和数据恢复机制也不完整。

### 2.2 第一阶段目标

让少量受邀教师无需安装客户端，通过桌面或手机浏览器使用同一套响应式产品，并达到：

- 能注册、登录、退出和找回密码；
- 未登录者不能访问业务 API、资料、OCR 结果或学生信息；
- 每位教师只能访问自己的班级、学生、资料、任务和批改记录；
- 部署、重启和升级后，SQLite、上传文件、OCR/解析产物与任务状态不丢失；
- PDF 查看不被 OCR/AI 长任务阻塞；
- 数据有可恢复副本，并完成一次真实恢复演练；
- 国内三网邀请测试达到本文件的上线门槛；
- 日常运维尽量使用 macOS、Node 和项目内脚本，降低额外学习成本。

### 2.3 当前产品范围

- 账号类型：平台所有者 1 人 + 少量受邀教师；
- 注册方式：邀请制，不开放任意访客注册；
- 数据关系：第一阶段“一位教师对应一个独立工作区”；
- 运行实例：一台 MacBook、一个 Node/Express 进程；
- 终端：响应式 Web，同一套前端和业务语义；
- 可用性：适合小规模试用，不承诺商业 SaaS 的 24×7 SLA。

## 4. 是否确实需要修改代码

需要。仅安装 Tunnel 或绑定域名不能解决以下问题：

1. 当前没有登录与数据隔离；
2. `/uploads` 可被知道路径的人直接访问；
3. 所有业务 repository 默认共享同一份数据库和 JSON；
4. Express 没有生产静态前端入口；
5. 任务重启恢复、健康检查、日志和备份不足；
6. 500 MiB 上传会超过本阶段代理与家庭上行的稳妥范围；
7. 旧数据必须归属到所有者工作区，不能继续作为所有账号共享数据。

## 5. 推荐的最短路径

### 5.1 为什么不默认购买服务器

主要计算和数据仍在 MacBook，现阶段购买服务器只会增加费用和运维面。Cloudflare Tunnel 由 MacBook 主动建立出站连接，不要求家庭宽带拥有公网 IP，也不需要在路由器上开放入站端口。

服务器只解决两类问题：

- 免费全球线路在中国大陆实测不达标，需要更可控的境内入口；
- 监管、备案或运营要求明确需要中国大陆云资源。

在这两项尚未被验证前，提前购买服务器不符合最短路径。

### 5.2 域名和访问入口

- 使用已经购买并完成实名的 `unreached.cn`；
- 将域名 DNS 托管到 Cloudflare；
- MacBook 安装并运行 `cloudflared`；
- `app.<域名>` 通过 Tunnel 指向只监听本机地址的 Express；
- Express 同源提供页面、`/api` 和鉴权后的文件内容；
- 不开放家庭路由器端口，不直接暴露 MacBook IP。

Cloudflare 官方说明 Tunnel 是由源站建立的出站连接，无需公开可路由 IP：<https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/>。

### 5.3 中国大陆访问承诺边界

Cloudflare 免费全球网络不等于中国大陆加速。Cloudflare 官方说明其中国大陆网络是 Enterprise 的独立订阅，并要求有效 ICP：<https://developers.cloudflare.com/china-network/>。

因此本阶段不写“保证国内高速”，而采用可检验承诺：

1. 部署测试域名；
2. 关闭开发机代理对测试的影响；
3. 在中国电信、联通、移动的真实 4G/5G/宽带上测试；
4. 连续测试 48 小时，覆盖晚高峰；
5. 达到第 14 节门槛才扩大邀请；
6. 不达标则停止扩散，重新审批国内入口方案。

如果最终使用中国大陆云资源对外提供服务，需按服务商要求完成 ICP 备案。购买 `.cn` 域名、域名实名与 ICP 备案不是同一件事。

### 5.4 一个月阿里云建站权益的定位

用户给出的规格与阿里云万小智 AI 建站轻量版一致。官方帮助中心说明：

- 中国内地节点上线前需要 ICP 备案，审核通常约 1–20 个工作日：<https://help.aliyun.com/zh/document_detail/3043304.html>；
- 平台可以上传带 Dockerfile 的 `.tar` 应用并构建安装：<https://help.aliyun.com/zh/document_detail/3043908.html>；
- CDN 配额用尽后，网站可能展示兜底下线页：<https://help.aliyun.com/zh/document_detail/3039542.html>。

这项临时权益可以帮助办理备案，也可能用于国内入口的短期技术验证，但不是产品长期运行条件。在控制台只读核实以下条件之前，不把它选为权威运行环境：

1. Node 进程是否可长期运行并有明确重启策略；
2. 是否存在独立、不会随镜像更新清空的持久卷；
3. 持久空间实际配额是否覆盖当前约 322 MiB 数据及增长；
4. 是否能执行 Python、PaddleOCR/doc2md、`pdftoppm` 和 Sharp；
5. 单请求上传、动态请求、CPU、内存和任务超时限制；
6. 是否支持导出备份、离线恢复和版本回滚；
7. 10 GiB/年 CDN 是只计算静态资源还是也计算 PDF/上传流量；
8. 一个月权益到期后的续费价和应用/备案状态。

无论核查结果如何，第一阶段都继续使用 MacBook 作为权威源站；万小智最多用于备案验证、简单公开说明页或虚构数据实验，不能保存学生真实数据。该权益到期不应造成 DEMO 停止访问、数据丢失或需要紧急迁移。

## 6. 身份验证、授权与数据隔离

### 6.1 身份方案

推荐使用 Better Auth，而不是自行实现密码、Cookie 和找回密码。它已有 Express、React、SQLite 和邮箱密码支持，能与当前 ESM 项目直接集成：

- Express 集成：<https://better-auth.com/docs/integrations/express>
- SQLite 与邮箱密码：<https://better-auth.com/docs/installation>

第一阶段行为：

- 所有者在本地初始化第一个管理员账号；
- 所有者从设置页创建一次性邀请链接；
- 被邀请人填写邮箱、姓名和密码后注册；
- 邀请令牌只保存哈希、设置过期时间且只能使用一次；
- 注册完成后创建独立工作区，但不创建登录会话；页面返回登录表单，用户再次提交邮箱和密码后才建立会话；
- 教师资料使用注册时实际填写的姓名；首个所有者可绑定迁移候选，后续受邀教师的工作区初始为空；
- 支持登录、退出；邮箱验证和自助密码重置只有在自动事务邮件通道通过验证后启用，否则先采用邀请邮箱绑定 + 所有者人工重置；
- 不接 GitHub、微信或其他社交登录，减少外部依赖和用户学习成本。

### 6.2 会话与 Web 安全底线

- 使用 `HttpOnly`、`Secure`、同源 Cookie；
- 生产环境仅信任明确的 `APP_URL`；
- 同源部署，不为业务 API 开放任意 CORS；
- 对修改请求校验 Origin/同源，沿用认证框架的 CSRF 防护；
- 登录、注册、邀请验证、找回密码和上传接口分别限速；
- 增加安全响应头和合理 CSP；
- 错误响应不暴露绝对路径、密钥、SQL 和调用栈；
- 日志只记录 request ID、用户/工作区的不可逆标识、状态码、耗时和错误码，不记录密码、令牌、Cookie、学生姓名、OCR 正文和文件内容。

### 6.3 隔离模型

推荐“认证库 + 每工作区独立目录”，而不是第一阶段给现有每张业务表追加 `user_id`：

```text
var-web/
├── system/
│   └── auth.sqlite
├── workspaces/
│   └── <workspace-id>/
│       ├── data/
│       │   ├── roster.sqlite
│       │   ├── resources.sqlite
│       │   ├── operations.sqlite
│       │   ├── grading-tasks.json
│       │   └── parser-artifacts/
│       └── uploads/
└── backups/
```

理由：

- 现有 SQLite 与 JSON 已天然按文件组织，物理目录隔离比修改所有业务表更短；
- 路径解析错误时更容易拒绝访问，降低跨用户查询风险；
- 可以按工作区独立备份、恢复、导出和删除；
- 后续迁往 PostgreSQL 时仍可以把 `workspace-id` 作为明确租户边界。

所有业务请求必须先通过会话解析出服务端 `WorkspaceContext`。客户端提交的工作区 ID 不能直接决定磁盘路径。路径必须由服务端映射，并验证解析结果仍位于该工作区根目录内。

原有真实数据只迁入所有者工作区；新受邀教师从空工作区开始，不复制真实学生数据。

### 6.4 Agent Mail CLI 的安装和产品定位

用户指定的官方文档：<https://agent.qq.com/doc/cli-setup.md>。

安装前只读核查：本机有 Node `v24.11.1`、npm `11.6.2`，系统全局 npm 前缀为 `/usr/local`；安装前没有 `agently-cli` 和 `agently-mail` skill。

用户于 2026-09-07 明确批准后，已按官方顺序执行：

1. `npm install -g @tencent-qqmail/agently-cli`；
2. `npx skills add https://agent.qq.com --skill -g -y`；
3. 以 PTY 启动 `agently-cli auth login`，只把命令输出的原始授权 URL 交给用户，不改写 URL；
4. 用户在浏览器完成 OAuth 后，等待命令自行退出；失败或超时不自动重试；
5. 使用 `agently-cli +me` 验证并记录实际授权邮箱地址，不把 OAuth 令牌写入项目或日志。

实际结果：

- `agently-mail` skill 已安装到 `/Users/cxc/.agents/skills/agently-mail` 并复制给 Codex；安装器仅提示 PromptScript 不支持全局 skill，不影响 Codex；
- OAuth 成功，主邮箱为 `xcheng@agent.qq.com`；
- `agently-cli +me` 验证成功；
- OAuth 令牌未写入项目、文档或日志。

本机写入范围：

- `/Users/cxc/.local` 下的用户级 npm 包与命令入口；
- 用户目录下由 Agent Mail CLI 创建的 OAuth 配置；
- 用户级 agent skill 目录；
- 不修改 DEMO 代码、`.env` 或母文件夹 `var`。

当前 CLI 的发信命令采用两步确认，适合由 Agent 在用户授权后发送邀请，不适合作为 Web 应用无人值守发送邮箱验证和找回密码邮件。第一阶段有两条路径：

- 推荐起步：所有者在管理页生成绑定邮箱的一次性邀请，使用 Agent Mail 人工发出；密码遗忘由所有者生成一次性重置链接后人工发送；
- 自动化备选：后续接入提供正式事务邮件 API/SMTP 的服务，再启用自动邮箱验证和自助找回密码。

Agent Mail 不需要访问学生数据，只接收邀请人邮箱、邀请链接和必要的账号通知文案。

## 7. 前端、API 与文件的同源生产结构

Express 作为唯一公网应用入口：

```text
GET  /                         Vite 构建后的 SPA
ALL  /api/auth/*               注册、登录、会话
GET  /api/health/live          进程存活，不访问外部服务
GET  /api/health/ready         配置、工作区根目录和数据库可用
ALL  /api/*                    登录后业务 API
GET  /api/files/:assetId/...   登录、归属校验后的文件读取
```

- 删除公开的 `/uploads` 静态目录；
- 前端只保存业务资源 ID，不信任磁盘绝对路径；
- 文件下载支持 Range 请求，保证 PDF 浏览器预览和断点读取；
- 未知前端路由回退到 `dist/index.html`；
- `/api` 与文件错误不能被 SPA 回退吞掉；
- 开发环境继续由 Vite 代理，生产环境只启动 Express 一个入口。

## 8. 上传、OCR/AI 长任务与重启

### 8.1 上传限制

- 资料库远程单文件：80 MiB；
- 批改答卷远程单文件：25 MiB，单请求最多 20 个且增加总请求体上限；
- 课表/名册：20 MiB；
- 仅允许明确文件类型，并同时检查扩展名、MIME 和文件签名；
- 上传先写当前工作区临时目录，校验后原子移动；
- 达到限制时返回明确中文提示和本地导入指引。

Cloudflare 文档当前显示免费/Pro 代理请求体常见上限为 100 MB，因此应用使用 80 MiB 留出协议和代理余量：<https://developers.cloudflare.com/cache/concepts/default-cache-behavior/>。

大文件由所有者通过仅限 MacBook 本机的导入命令放入指定工作区。命令必须执行相同的类型校验、数据库登记和审计，不允许简单复制文件后绕过产品状态。

### 8.2 OCR 运行方式

- 有原生文本的 PDF：优先本机提取，不做无意义 OCR；
- 扫描 PDF/图片：优先现有 PaddleOCR 远程 API；
- DOCX：保留本机 Python/doc2md 流程；
- PDF 页面渲染与裁切：保留 MacBook 上的 `pdftoppm`、Python/Sharp 等本地工具；
- OpenAI-compatible 模型：继续远程调用，密钥只存在服务端环境。

因此不需要把 PaddleOCR、Python 或 PDF 工具部署到另一台服务器；它们运行在作为源站的 MacBook 上。生产启动检查只验证命令是否存在，不输出密钥。

### 8.3 异步任务和并发

超过普通请求时长的 OCR/AI 操作改为：

```text
提交任务 → 返回 jobId → 前端查询状态 → 展示阶段/进度/错误 → 可重试或人工接管
```

任务状态持久化到对应工作区的 `operations.sqlite`。启动时把残留的 `running` 标记为 `interrupted`，安全任务可人工重试；不得假装自动续跑已经失去上下文的任务。

不限制整个系统为单并发。只按本机资源类型设置保护：

- 普通读取、PDF Range 请求和状态查询始终可并发；
- 本地高 CPU/高内存解析任务默认同时 1 个；
- 远程 OCR/AI 任务按供应商限制和本机内存配置小并发；
- 并发值通过环境配置并在实测后调整；
- 单个工作区的异常不得阻塞其他用户查看已有资料。

## 9. MacBook 生产运行与可用性

- Node 只监听 `127.0.0.1`，公网入口只有 Tunnel；
- 使用 macOS `launchd` 管理 Node 和 `cloudflared` 的开机启动与异常重启；
- 不依赖长期打开的 Terminal 窗口；
- MacBook 开启 FileVault、强密码和自动锁屏；
- 服务账号不授予不必要的系统权限；
- 电源设置避免服务期间睡眠，但保留安全更新维护窗口；
- 优雅退出时停止接收新任务、等待短请求、将未完成任务持久化并关闭 SQLite；
- 磁盘空间不足、数据库不可写或关键目录不可访问时，就绪检查失败并拒绝新写入；
- Tunnel 中断、宽带断线、Mac 休眠和系统重启都会造成外部不可用，这是本方案的明确代价。

## 10. 数据副本迁移、切换与回滚

### 10.1 不可变规则

- 不拿母文件夹唯一真实数据试错；
- SQLite 使用在线备份，不能只复制 `.sqlite` 主文件；
- 每次迁移生成带时间戳的目录、清单、文件大小和 SHA-256；
- 迁移程序只读取母文件夹 `var`，写入新的 staging/工作区；
- 未完成校验前，不改变权威数据指向。

### 10.2 第一次演练

1. 为 `roster.sqlite`、`resources.sqlite` 分别执行 SQLite 在线备份；
2. 对上传、OCR 分页、解析产物和 JSON 状态创建文件快照；
3. 生成源清单和哈希；
4. 将副本导入 `var-web/staging/<时间戳>/owner-workspace`；
5. 运行两库 `PRAGMA integrity_check`；
6. 对照班级、学生、课表、日程、资源、页面、块、知识节点和任务数量；
7. 校验数据库引用的每个文件存在且位于工作区根目录；
8. 用临时端口启动新服务，完成只读 UI 烟雾测试；
9. 删除 staging 前先保留演练报告，不删除母文件夹数据。

### 10.3 正式切换

1. 公告短维护窗口并阻止旧版本新写入；
2. 再做一次 SQLite 在线备份与文件增量快照；
3. 复用演练过的校验流程；
4. 把 `current` 指针切到通过校验的工作区副本；
5. 启动生产服务并验证登录、资料读取和关键数量；
6. 母文件夹原 `var` 冻结为切换前恢复点，不覆盖、不删除。

### 10.4 回滚

- 代码失败：停止新服务，恢复旧启动方式并指回冻结的母文件夹 `var`；
- 数据迁移失败：丢弃失败的 staging 副本，不触碰源数据；
- 切换后产生新写入再回滚：先冻结 `var-web` 并备份，不能直接回到旧数据后继续写；需记录差异并决定前向修复或人工合并；
- 认证失败：可从本机维护命令禁用外部入口或重置所有者会话，不绕过业务数据授权。

## 11. 备份与恢复方案

### 11.1 备份层级

1. 每 6 小时：所有 SQLite 在线备份 + 新增/变化文件快照；
2. 每晚：生成完整校验清单和加密归档；
3. 每周：把加密归档复制到异地位置；
4. 每月：恢复到临时目录并执行自动校验与 UI 抽查。

本机同一磁盘上的备份只能防误操作，不能防硬盘损坏、丢失或勒索。异地副本第一阶段可选 macOS 自带 iCloud Drive 中的加密备份归档，或外接加密硬盘；不把正在使用的 SQLite 直接放入同步盘。

建议目标：

- RPO（最多可接受的数据损失）：6 小时；
- RTO（从故障到恢复可用）：2 小时；
- 本地保留：7 天滚动 + 4 个周备份；
- 删除备份前必须先有一个已验证的替代恢复点。

### 11.2 恢复验证

恢复永远先落到新的临时目录，不覆盖当前运行目录。验证包括：

- SQLite `integrity_check`；
- 关键表和 JSON 任务数量；
- 文件引用存在性、大小与哈希抽检；
- 所有者与普通教师的跨工作区拒绝测试；
- 登录、班级、资料、PDF、OCR 结果、知识结构和批改记录烟雾测试；
- 验证完成后由用户决定是否切换。

## 12. 日志、健康检查和人工接管

### 12.1 健康检查

- `live`：进程事件循环可响应；
- `ready`：配置合法、工作区根目录可读写、认证库可访问；
- 依赖状态：单独展示 AI/OCR 是否配置和最近调用状态，不因第三方短暂故障让 PDF/本地数据整体不可用。

### 12.2 结构化日志

日志字段限定为：时间、级别、事件、request ID、匿名用户/工作区 ID、路由模板、状态码、耗时、任务 ID、错误码。敏感正文、文件名、邮箱、学生姓名和第三方响应默认不记录。

### 12.3 人工控制

所有者可以：

- 暂停新邀请；
- 撤销某个用户的全部会话；
- 禁用某个账号但保留数据；
- 暂停 OCR/AI 新任务；
- 查看失败阶段并触发安全重试；
- 关闭 Tunnel，立即停止互联网入口；
- 从验证过的备份恢复到临时目录后再决定切换。

## 14. 验收与上线门槛

### 14.1 功能和隔离

- 未登录访问业务 API 和文件均返回拒绝；
- 用户 A 猜测用户 B 的资源 ID、任务 ID 或文件路径时仍无法访问；
- 普通用户不能创建邀请、查看账号列表或操作系统备份；
- 注册邀请过期、重复使用和篡改均失败；
- 登录、退出、会话过期、邮箱验证和密码重置流程通过；
- 所有者真实数据完整迁入所有者工作区，新用户工作区为空。

### 14.2 数据和恢复

- 服务和 MacBook 重启后数据与任务状态仍存在；
- 两个 SQLite 完整性检查为 `ok`；
- 关键表数量和文件引用与迁移报告一致；
- 从备份恢复到临时目录并完成端到端读取；
- 恢复失败不会覆盖当前权威数据。

### 14.3 长任务

- OCR/AI 请求快速返回 `jobId`；
- 运行中可以查看阶段、耗时和错误；
- 任务失败或进程重启后状态不消失；
- 任务运行期间可以继续浏览 PDF 和其他已完成资料；
- 重试不会创建不受控的重复正式结果。

### 14.4 响应式产品

按 `docs/design.md` 的尺寸矩阵验证 375×812、390×844、430×932、844×390、768×1024、1024×768、1440×900。核心流程在手机和桌面使用同一后端、同一数据状态，不建立独立手机版逻辑。

### 14.5 国内网络准入

测试对象至少覆盖中国电信、联通、移动各一条真实网络，并覆盖一次 19:00–23:00 时段：

- 连续 48 小时无区域性无法连接；
- 登录与普通页面请求成功率不低于 99%；
- 登录后工作台首屏 P95 不超过 5 秒；
- 本地数据读取 API P95 不超过 1.5 秒；
- 10 MiB PDF 首次可见内容 P95 不超过 8 秒；
- 50 MiB 上传在前端有连续进度，失败可安全重试且不产生脏记录；
- 微信内置浏览器和主流手机浏览器均能完成登录、查看和轻量编辑。

这些是第一版候选门槛。若目标试用者实际网络普遍无法达到，不降低数据安全标准来换速度，而是暂停扩散并提交国内入口备选方案。

## 17. 备选方案与触发条件

### 17.1 可选实验：一个月万小智共享 ECS

这不是长期部署备选，只是已有一个月权益内的可选实验。若时间允许，可用虚构数据核查第 5.4 节八项边界，帮助未来理解阿里云容器产品。不得因为短期免费而迁移权威数据，也不以续费为本阶段前提。

### 17.2 备选 B：中国大陆轻量服务器只做入口

触发条件：三网实测持续不达标，且用户愿意承担服务器、备案和运维成本。服务器只做 HTTPS 入口/反向代理，不承载权威业务数据和 OCR；仍需评估服务器到家庭网络的安全隧道与延迟。

缺点是链路更长、仍依赖 MacBook在线，并增加备案与维护；所以不是默认方案。

### 17.3 备选 C：整套迁移到中国大陆服务器

触发条件：MacBook 可用性或家庭上行被证明确实不够，且用户接受持续费用。Node、SQLite、文件、Python/PDF 工具全部迁移到持久磁盘服务器。

缺点是硬件规格、持久磁盘、OCR 依赖与备份会带来更高成本；不属于本阶段批准范围。

### 17.4 备选 D：未来 SaaS 数据层

只有多人并发、跨实例或协作编辑经过验证后，才考虑 PostgreSQL、对象存储、持久队列和租户级审计。第一阶段不提前实施。

| Cloudflare 免费线路国内波动 | 页面慢或不可达 | 三网 48 小时硬验收、失败暂停扩散 | 不能承诺全国一致速度 |
| 家庭宽带上行有限 | PDF/上传慢 | 80 MiB 限制、大文件本地导入 | 用户体验受家庭线路影响 |
| Mac 睡眠、断电或重启 | 全部外部访问中断 | `launchd`、电源设置、健康检查 | 无第二台机器时仍是单点 |
| Mac 丢失或硬盘损坏 | 数据不可用/泄露 | FileVault、异地加密备份、恢复演练 | 需要维护恢复密钥和备份介质 |
| 文件目录隔离实现错误 | 跨用户泄露 | 服务端工作区映射、路径约束、越权测试 | 仍需持续安全审查 |
| 免费邮件投递不稳定 | 无法验证/重置密码 | 发信域名验证、重试、真实国内邮箱测试 | 可能需要更换服务商 |
| Agent Mail 需要发信确认 | 无法自动发送系统邮件 | 先用于少量人工邀请与人工重置 | 规模扩大后仍需事务邮件 API/SMTP |
| 万小智共享 ECS 边界不明 | 升级丢数据、任务被终止 | 仅用虚构数据验证持久化、重启和备份 | 一个月权益可能不足以完成长期验证 |
| OCR/AI 长任务耗资源 | 页面卡顿或进程崩溃 | 任务持久化、按资源类型并发、内存观测 | 单机吞吐有限 |
| JSON 状态并发写 | 丢更新 | 原子写入；关键运行状态迁入 SQLite | 迁移范围较大 |
| 备案/宽带使用条款不确定 | 公网试用受限 | 公网前核对注册商、运营商及适用要求 | 可能触发国内云资源方案 |

## 19. 本阶段明确不做

- 不开放公共自由注册；
- 不接入支付、订阅和商业化计费；
- 不做学校、教研组、学生端或多人协同编辑；
- 不改成微服务；
- 不迁移 PostgreSQL、对象存储或分布式任务队列；
