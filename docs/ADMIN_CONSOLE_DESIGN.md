# 管理后台信息架构与首期设计

> 版本：v1.0
> 日期：2026-10-14
> 状态：设计方案；尚未实施代码
> 基线：`origin/main@d7c3ca6`

## 本次概要

把平台管理员处理账号的工作场景与教师处理教学任务的工作场景分开。首期复用已经存在的账号管理接口，提供清楚的进入与返回路径，不把尚未生效的设置项搬进后台。

## 1. 问题、目标与边界

- 当前邀请、账号列表和重置链接藏在「系统设置 → 教师信息」中；账号管理与教师资料混在一页。
- 管理员同时是一位教师，仍应在自己的独立工作区完成教学任务。
- 首期目标是让管理员能找到并完成已有的账号管理任务，且始终知道自己处于管理后台还是教师工作台。
- 管理入口不赋予跨工作区读取权限。其他教师的班级、学生、资料、作业和批改结果不属于首期后台内容。
- 不把服务器密钥、数据路径、部署、备份和恢复操作做成普通网页表单。

## 3. 借鉴与取舍

- [Shopify App Navigation](https://shopify.dev/docs/apps/design/navigation)：按任务组织少量、易扫描的导航项；页面提供明确的返回路径，手机与桌面维持同一信息架构。
- [Microsoft 365 Admin Center](https://learn.microsoft.com/en-us/microsoft-365/admin/admin-overview/admin-center-overview?view=o365-worldwide)：把用户与权限、服务状态等平台任务与普通使用者任务区分。
- [USWDS Side Navigation](https://designsystem.digital.gov/components/side-navigation/)：页面数量少时避免为了“后台感”增加不必要的层级。

借鉴的是结构原则，不复制大型平台的页面数量和视觉外壳。当前最短路径是独立管理场景中的单个「账号与邀请」页面。

## 4. 页面地图与导航

```text
教师工作台
├─ 教学工作、家校管理、资料库等现有业务页面
├─ 我的设置：教师资料、作息、个人偏好
└─ 账号菜单（仅 owner 显示「进入管理后台」）
    └─ 管理后台 /admin/accounts
       ├─ 顶部标识「管理后台」
       ├─ 固定可见的「返回教师工作台」
       └─ 账号与邀请
          ├─ 创建邀请
          ├─ 账号列表与状态
          ├─ 待使用邀请与撤销操作
          └─ 为账号生成密码重置链接
```

进入后台、刷新页面或直接打开 `/admin/accounts`，均须先确认登录身份和 `owner` 角色。非管理员应看到可理解的无权限提示和返回教师工作台入口；页面隐藏只能改善体验，不能代替服务端鉴权。返回时优先恢复进入前的教师页面；若没有可恢复状态，则返回工作台首页。退出登录后清除后台页面状态。

首期只在账号菜单放一个入口，避免把「管理后台」混进教师业务侧栏。后台页面不复制教师侧栏；若后来出现多个已验证的管理任务，再增加后台局部导航。桌面端与手机端是同一功能：手机上账号入口、返回操作、邀请表单和列表行内操作都要可触控，窄屏与矮屏不遮挡主要操作。

## 5. 内容归属

| 内容 | 归属 | 理由与条件 |
| --- | --- | --- |
| 账号、邀请、撤销、重置链接 | 管理后台首期 | 跨用户的平台管理任务，已有 `owner` API。 |
| 账号停用、角色调整、使用配额 | 管理后台候选 | 当前无完整产品规则和接口；涉及可恢复性与权限变更，需另定方案。 |
| AI/OCR 服务状态和任务故障反馈 | 管理后台候选 | 需要能区分「已配置」「实际调用成功」「当前故障」的证据；不能仅凭 ready 状态宣称可用。 |
| 平台级功能开关、默认模型或供应商 | 管理后台候选 | 先确定生效范围、变更审计、失败回退和密钥处理。 |
| 教师资料、外观、自己的教学偏好 | 教师工作台「我的设置」 | 作用范围是当前教师，而非整个平台。 |
| 班级、学生、班委、标签、课表、材料池与资料 | 对应教师业务页面 | 是日常教学对象，仍按当前工作区隔离。 |
| 评分/OCR 阈值 | 暂不迁移 | 当前页面描述与实际控制链不一致；详见 `AI_GRADING_THRESHOLD_PENDING.md`。 |
| 密钥、服务器路径、部署、数据库备份和恢复 | 现有运维流程 | 当前阶段不开放网页写入；未来若需要，必须单独设计授权、审计和恢复。 |

## 6. 首期页面行为

- 账号和邀请按状态分组，列表显示姓名、邮箱、角色与状态；不要显示其他教师的业务数据。
- 创建邀请成功后明确显示一次性链接及到期时间；复制成功、失败均给出反馈。人工发送仍按当前约定执行。
- 仅待使用邀请显示「撤销」；撤销前确认目标邮箱，成功后刷新状态，失败时保留原列表并说明原因。
- 生成密码重置链接前确认目标账号；生成后显示有效期与复制操作，不自动发送给第三方。
- 加载失败、无数据和操作失败分别处理。错误信息说明本次变更是否保存及下一步操作。
- 所有管理写操作继续走现有同源请求、会话和服务端 `owner` 校验。不得通过前端模式切换提升权限。

## 7. 实施范围与验证门槛

本文件仅批准设计文档，不授权代码修改。后续代码方案预计涉及 `src/app/navigation.ts`、`src/app/AppLayout.tsx`、`src/App.tsx`、`src/features/settings/AccountAccessPanel.tsx` 与 `src/features/settings/SystemSettingsPanel.tsx`；具体文件范围需在实施前重新确认。

后续验收至少覆盖：管理员和普通教师的进入/直达边界；进入、返回、刷新、退出登录；邀请创建与撤销、重置链接；失败反馈；桌面与窄屏/矮屏手机的真实应用壳层触控和滚动。不得用构建通过替代真实界面验收。

## 8. 风险与暂不做

- 首期仅重组已有账号任务，不代表所有当前设置项已可持久化或生效。
- 不新增空概览页、跨工作区教学数据浏览、账号冒用、在线密钥编辑、备份恢复按钮。
- 邀请和重置链接属于敏感短期凭证，界面不应在无关页面长期展示或写入普通日志。
