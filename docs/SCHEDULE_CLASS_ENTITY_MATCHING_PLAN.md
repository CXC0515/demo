# 课表班级实体匹配方案

## 文档信息

- 当前版本：v1.1
- 日期：2026-09-09
- 状态：已完成本地实施与隔离验证，等待推送、合并和部署授权
- Git 基线：`origin/main@29ded49`

## 1. 原始问题与目标

同一张教师课表在不同识别请求中可能出现不同结果：课程、星期和课节可以识别，但已有班级偶尔显示“待确认”。目标不是针对“初一（9）班”和“初一（10）班”添加特例，而是建立适用于任意已有班级名称的实体匹配闭环。

系统必须做到：

1. 只在当前登录教师的启用班级目录内匹配；
2. 同时利用 OCR 单元格原文、AI 候选和本地确定性规则；
3. 唯一可靠时自动匹配，冲突或歧义时交给教师确认；
4. 教师可把相同识别写法一次映射到同一个已有班级；
5. “尚未确认”和“明确不关联班级”是两个不同状态；
6. 未处理的待确认项目不能直接写入正式课表。

## 2. 已确认事实

- 线上两个工作区均存在“初一（9）班”和“初一（10）班”，不是数据隔离导致班级不可见。
- 使用问题照片、工作区数据副本和线上同一 OCR/AI 配置隔离复现时，12 节课全部成功匹配。
- 当前链路依赖 AI 返回可匹配的 `className`；AI 返回空值或非标准写法时缺少可靠兜底，因此结果具有偶发性。
- 上一次待确认草稿未保存到正式课表，真实数据没有受到影响。
- 历史 AI 响应和临时上传按现有策略不保留，无法还原当次具体错误文本。

## 3. 决策

采用“已有班级目录约束 + OCR 原文证据 + AI 候选 + 本地实体匹配 + 教师复核”。

- AI 在原有一次结构化请求中返回 `recognizedClassText` 和目录候选 key，不增加第二次模型请求。
- Prompt 要求逐字保留课程格中的班级原文，候选 key 只能来自当前教师已有班级目录，无法唯一判断时必须留空并说明原因。
- 后端验证候选属于当前工作区，并按完整名称、规范化名称、年级/班号别称等证据裁决。
- 任意自定义名称可通过完整名称或目录约束候选匹配；规则不限定为数字班级。
- OCR 与 AI 冲突、同名不同学期或多个合理候选时不自动猜测。
- 本阶段不新增永久别名表。先观察三个试用用户的真实样本，再决定是否需要工作区别名库。

## 4. 交互与状态

- 自动匹配项显示“已自动匹配”和识别原文。
- 待确认项集中显示在草稿顶部；选择一次应用到草稿内所有相同识别文字。
- 单节课程仍允许覆盖批量结果。
- 教师可以明确选择“不关联班级”。
- 只要仍有 `unresolved` 项，确认写入按钮保持禁用并显示剩余数量。
- Compact 模式使用全屏草稿，表单控件不低于 44px，输入字号不低于 16px；宽屏保留批量核对效率。

## 5. 数据与安全边界

- 不修改 SQLite 表结构，不迁移或改写已有班级和课表。
- 正式保存前移除草稿专用的识别证据与状态字段。
- 日志只记录项目数、已匹配数、待确认数和原因码统计，不记录学校、教师、班级名称或 OCR 原文。
- 服务端拒绝当前工作区目录以外的 AI 候选编号。

## 6. 验证

- 单元测试：任意名称、数字别称、全半角、AI 空值、无效候选、冲突、同名不同学期。
- 服务测试：Prompt 目录约束、识别原文保留、本地兜底和输出状态。
- UI 验证：桌面与 390px 手机完成自动匹配、批量确认、单项覆盖、不关联和提交拦截。
- 隔离复现：仅使用 SQLite 在线备份和图片副本，不写权威数据。
- 基础检查：`npm run lint`、`npm run test:schedule`、`npm run build`。

## 7. 明确不做

- 不写死某几个班级名称；
- 不自动创建班级；
- 不新增永久别名数据库；
- 不增加第二次 AI 请求；
- 不保存 OCR 原文到日志；
- 不调整 OCR 供应商或重构整个课表模块。
