# 课表班级实体匹配方案

## 文档信息

- 当前版本：v1.6
- 日期：2026-09-10
- 状态：v1.4 根因修复已通过 PR #16 部署，待真实课表验收
- Git 基线：`origin/main@52754d1`

## 1. 原始问题与目标

同一张教师课表在不同识别请求中可能出现不同结果：课程、星期和课节可以识别，但已有班级偶尔显示“待确认”。目标不是针对“初一（9）班”和“初一（10）班”添加特例，而是建立适用于任意已有班级名称的实体匹配闭环。

系统必须做到：

1. 只在当前登录教师的启用班级目录内匹配；
2. 同时利用 OCR 单元格原文、AI 候选和本地确定性规则；
3. 唯一可靠时自动匹配，冲突或歧义时交给教师确认；
4. 教师可把相同识别写法一次映射到同一个已有班级；
5. “尚未确认”和“明确不关联班级”是两个不同状态；
6. 未处理的待确认项目不能直接写入正式课表。

## 2. 已确认事实

- 线上两个工作区均存在“初一（9）班”和“初一（10）班”，不是数据隔离导致班级不可见。
- 使用问题照片、工作区数据副本和线上同一 OCR/AI 配置隔离复现时，12 节课全部成功匹配。
- 当前链路依赖 AI 返回可匹配的 `className`；AI 返回空值或非标准写法时缺少可靠兜底，因此结果具有偶发性。
- 上一次待确认草稿未保存到正式课表，真实数据没有受到影响。
- 历史 AI 响应和临时上传按现有策略不保留，无法还原当次具体错误文本。
- 2026-09-10 隔离实验中，PaddleOCR 首次真实返回“任务提交队列已满”；随后固定同一份 OCR 文本连续请求 AI 三次，三次均为 HTTP 200 且 12 项映射一致。远程服务可用性和班级关联是两个独立故障层。
- 当前课表 AI 只接收 OCR 文本，不接收原图。其职责应是依托封闭班级目录清理 OCR 噪声，而不是替代 OCR 重新识字。
- v1.2 Prompt 同时要求 `recognizedClassText`、`className` 和临时候选 key，重复结论可能互相矛盾；示例又使用具体十班和 `C1`，存在不必要的候选偏向。

## 3. 决策

采用“已有班级目录约束 + OCR 原文证据 + AI 候选 + 本地实体匹配 + 教师复核”。

- AI 保留 OCR 班级原文，只返回封闭目录候选、纠错类型和复核状态；标准班级名称由服务端通过候选 key 获取，不再让 AI 重复返回 `className`。
- Prompt 使用中性字段说明，不出现具体班级或首个候选示例；明确相同 OCR 写法必须获得相同映射。
- 相同 OCR 写法由服务端分组后只裁决一次。首次结果冲突时，仅对冲突写法增加一次聚焦 AI 复核，不重复生成整张课表。
- 后端验证候选属于当前工作区，并按完整名称、规范化名称、年级/班号别称等证据裁决。
- AI 可以把疑似涂改字、污迹字符和重复字清理为目录中的已有班级，但服务端拒绝改变清晰年级或班号、目录外候选和改动幅度过大的纠错。
- 任意自定义名称可通过完整名称或目录约束候选匹配；规则不限定为数字班级。
- OCR 与 AI 冲突、同名不同学期或多个合理候选时不自动猜测。
- 本阶段不新增永久别名表。先观察三个试用用户的真实样本，再决定是否需要工作区别名库。

## 4. 交互与状态

- 自动匹配项显示“已自动匹配”和识别原文。
- AI 清理 OCR 噪声后显示“AI 已清理 OCR 噪声”，原始文字仍可见。
- 待确认项集中显示在草稿顶部；选择一次应用到草稿内所有相同识别文字。
- 单节课程仍允许覆盖批量结果。
- 教师可以明确选择“不关联班级”。
- 只要仍有 `unresolved` 项，确认写入按钮保持禁用并显示剩余数量。
- Compact 模式使用全屏草稿，表单控件不低于 44px，输入字号不低于 16px；宽屏保留批量核对效率。

## 5. 数据与安全边界

- 不修改 SQLite 表结构，不迁移或改写已有班级和课表。
- 正式保存前移除草稿专用的识别证据与状态字段。
- 日志只记录项目数、已匹配数、待确认数和原因码统计，不记录学校、教师、班级名称或 OCR 原文。
- 服务端拒绝当前工作区目录以外的 AI 候选编号。
- PaddleOCR 排队、限流、超时以及 AI 连接失败、502、503、504 只进行有限重试；日志记录阶段、错误码和重试结果，不记录 OCR 原文。

## 6. 验证

- 单元测试：任意名称、数字别称、全半角、AI 空值、无效候选、冲突、同名不同学期。
- 服务测试：Prompt 目录约束、识别原文保留、本地兜底和输出状态。
- UI 验证：桌面与 390px 手机完成自动匹配、批量确认、单项覆盖、不关联和提交拦截。
- 隔离复现：仅使用 SQLite 在线备份和图片副本，不写权威数据。
- 基础检查：`npm run lint`、`npm run test:schedule`、`npm run build`。
- 回归样本必须包含 OCR 噪声清理、班号锚点冲突、同一写法重复出现、首次 AI 候选冲突和上游服务短暂失败。

## 7. 明确不做

- 不写死某几个班级名称；
- 不自动创建班级；
- 不新增永久别名数据库；
- 不对正常映射增加第二次 AI 请求；
- 不保存 OCR 原文到日志；
- 不调整 OCR 供应商或重构整个课表模块。

## 8. 后续产品议题：班级生命周期与升学

后续单独调查班级是否跨学期延续、整班升学、学生升年级、分班以及历史课表和学情归档。本轮只保留现有学期字段，不修改班级数据模型；普通班级选择只显示纯班级名，真正重名时才附加学期。

## 10. 实施记录

### v1.4（已部署，待真实课表验收）

- 线上日志确认班级课表共 34 项，`matchedCount=0`、`unresolvedCount=34`，原因全部为 `no-candidate`；教师字段为空不是触发条件。
- 两个真实工作区分别存在 2 个和 4 个启用班级，母级兼容数据库的启用班级数为 0。multipart 上传完成后的异步回调没有重新进入认证工作区，是当前证据唯一一致解释，也属于资料与批改上传共用的数据隔离风险。
- 修复落在认证工作区边界：认证后把工作区绑定到请求，所有 authenticated multipart 路由使用该请求的上传目录，并在 Multer 完成后重新进入相同工作区；课表匹配器没有名称特例或母级数据库静默回退。
- 班级课表必须在 OCR 前验证 `classId`；无效时立即拒绝，避免消耗 OCR/AI 后生成无法操作的草稿。
- 班级课表的班级已经由教师在页面选择，不再生成或统计班级待确认状态；教师字段允许为空。AI 仅输出星期、课节、课程、可空教师和置信度，减少冗余生成。
- 功能提交 `2b77458` 已通过 PR #16 合并为远端 `main@52754d1` 并部署；远端和本地功能分支及本次 worktree 已删除。
- `npm run lint`、`npm run build` 和 28 项课表测试全部通过；工作区隔离、班级可视化、资料、批改与视觉验证相关测试也全部通过。未消耗真实 OCR/AI 额度，线上实际延迟留待部署后的单次真实导入验收。

### v1.3（已部署）

- AI 输出收敛为 OCR 原文、封闭目录候选 key、纠错类型和复核状态；标准班级名称只由服务端目录提供。
- 服务端按规范化后的 OCR 原文分组。同一写法只裁决一次；首次候选冲突时仅复核冲突组，并把结果应用到该组全部课程。
- 实体匹配器允许小幅 OCR 噪声清理，同时校验年级、班号锚点、当前工作区候选和改动幅度；AI 不确定或改变清晰班号时保持待确认。
- PaddleOCR 排队、限流、超时和解析暂时失败最多尝试 3 次，退避 5 秒、15 秒；AI 连接错误及 502/503/504 最多尝试 3 次，退避 1 秒、3 秒。最终失败按阶段返回可理解提示。
- 班级下拉只在启用班级出现同名歧义时附加学期；普通情况只显示班级名称。草稿明确区分自动匹配、AI 清理 OCR 噪声、教师确认和不关联班级。
- UI 对重复查找使用派生的 `Map`，响应式草稿仍保持单一状态源；桌面和手机使用同一套交互。
- 未修改 SQLite 表结构、权威数据库、正式课表或永久别名数据。
