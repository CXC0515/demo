# DEMO 自适应产品设计规范

## 1. 文档定位

本文件是 DEMO 教师端在桌面、平板和手机上的界面设计契约。它记录产品层面的设计事实、适配原则、页面行为和验收标准；具体组件仍可根据任务调整，但不得破坏这里定义的可读性、控制权和状态连续性。

本规范解决的是“同一任务如何在不同设备上有效完成”，不是把桌面界面等比例缩小。桌面端可以同时展示多个工作区域，手机端必须根据教师当前任务重新编排信息层级。

适用范围：

- 应用壳层、导航、页面标题和全局反馈；
- 工作台、课表日程、班级与学生、学情诊断、资料库和设置；
- PDF/OCR 阅读、知识图谱、表格、批量操作、抽屉和弹窗；
- 后续新增的所有业务页面。

暂不决定最终交付形态是响应式 Web、PWA、壳应用还是原生 App。当前先建立平台中立的响应式 Web 基线，使未来迁移不依赖桌面专用交互。

## 2. 目标、事实与主要矛盾

### 目标

1. 教师可以在手机上完成查看、定位、记录、审核和轻量编辑，而不是只能浏览缩小版桌面页面。
2. 桌面端保留适合批量处理和多信息对照的工作效率。
3. 设备尺寸变化时，业务状态、当前对象和操作结果连续，不因布局切换丢失。
4. 每个关键功能都可观察、可返回、可纠正，不用隐藏状态换取视觉简洁。

### 已确认事实

- 应用已有移动导航抽屉，但各业务页面没有统一的响应式契约。
- 资料编辑使用桌面多栏、固定视口高度和最小高度；窄屏堆叠后会挤压 PDF 阅读区。
- 知识图谱默认把整张图适应到视口，并使用很小的节点文字；小屏上“看到全图”和“读懂内容”无法同时成立。
- 项目中存在固定列宽、固定高度、9–10px 文字和只适合桌面表格的页面。

### 主要矛盾

主要矛盾不是缺少某个 CSS 断点，而是桌面端“同时看多个区域”的信息架构与手机端“一次完成一个主要任务”的使用方式冲突。

因此，适配优先顺序为：

1. 保证主要任务完整可完成；
2. 保证当前对象和状态可追溯；
3. 保证文字、触控和阅读区域可用；
4. 再增加同屏信息密度和装饰效果。

## 3. 自适应尺寸模型

断点代表界面能力，不代表某个具体设备品牌。

| 模式 | 参考宽度 | 信息编排 | 典型设备 |
| --- | ---: | --- | --- |
| Compact | `< 640px` | 单一主要工作面，次要内容进入新层级或底部抽屉 | 手机竖屏、窄窗口 |
| Medium | `640–1023px` | 主工作面稳定显示，辅助区按需覆盖或并列 | 手机横屏、平板 |
| Wide | `1024–1439px` | 双栏或有限三栏，可长期显示上下文 | 笔记本、普通显示器 |
| Extra Wide | `>= 1440px` | 增加辅助信息密度，不放大主要阅读宽度 | 大显示器 |

除宽度外，页面必须处理：

- `100dvh` 与浏览器动态工具栏；
- iOS/Android 安全区域；
- 软键盘弹出后的可视高度；
- 横屏和低高度窗口；
- 浏览器 200% 缩放；
- 系统字体放大和减少动态效果。

禁止仅依据设备名称或 user-agent 决定布局。优先使用容器能力、CSS 媒体查询和实际可用空间。

## 4. 全局界面契约

### 4.1 页面壳层

- Compact：顶部栏只保留导航入口、当前页面/对象和一个主要操作；全局班级、账号等信息进入菜单或上下文选择器。
- Medium：允许在顶部显示当前班级等关键上下文，次要信息继续收起。
- Wide：显示固定侧栏和完整上下文，但主要内容宽度仍应受阅读与任务效率约束。
- 页面切换后必须关闭临时导航层，并把焦点送到新页面的主要标题或主要工作区。

### 4.2 信息层级

- 每个页面只定义一个主要任务和一个主要操作。
- 手机端一次只长期展示一个主要工作面；辅助面板使用抽屉、底部面板或下一级页面。
- 不因空间不足删除功能。应改变入口和层级，并保留明确的返回路径。
- 当前班级、学生、资料、页码和筛选条件属于业务状态，跨布局变化必须保留。

### 4.3 字体与触控

| 类型 | 最低建议值 |
| --- | ---: |
| 正文 | 14px，主要阅读内容优先 16px |
| 辅助文字 | 12px |
| 表单输入 | 16px，避免移动 Safari 自动放大 |
| 可操作区域 | 44 × 44px |
| 相邻高风险操作间距 | 8px |

9–10px 只能用于非必要、无需持续辨认的装饰性标记，不能承载名称、状态、数量、页码或操作含义。不得禁止页面缩放。

### 4.4 间距和容器

- Compact 页面外边距默认 12–16px；卡片内部默认 12–16px。
- Medium 页面外边距默认 16–20px。
- Wide 页面外边距默认 24px。
- 阅读正文应限制舒适行长；大屏增加留白或辅助区域，不无限拉宽文本。
- 圆角、阴影和玻璃效果不能造成内容边界不清或低对比度。

### 4.5 滚动与高度

- 一个视图应有可解释的主要滚动容器，避免页面、卡片、列表和阅读器四层嵌套滚动。
- 不得用 `100vh - 固定像素` 配合大 `min-height` 模拟工作台高度。
- 使用 `dvh`、弹性布局和 `min-height: 0` 让主要工作区获得真实剩余空间。
- 切换标签、页码或模式时保留旧内容，直到新内容就绪；不得用白屏表示加载。
- 页面跳转和自动定位应尊重 `prefers-reduced-motion`。

## 5. 通用组件的自适应行为

| 桌面形态 | Compact 形态 | 关键约束 |
| --- | --- | --- |
| 固定侧栏 | 导航抽屉 | 返回后保持原页面状态 |
| 三栏工作台 | 单工作面 + 底部抽屉/下一级页面 | 不把三栏纵向堆成长页面 |
| 数据表格 | 优先字段卡片、分段列表或可控横向表格 | 排序、筛选和批量选择仍可用 |
| 右侧详情面板 | 底部抽屉或全屏详情 | 显示明确关闭和返回入口 |
| 多按钮工具栏 | 主要操作 + “更多”菜单 | 主要操作位置稳定 |
| 多列表单 | 单列或少量相关字段成组 | 标签在输入框附近，错误不只靠颜色 |
| 图表/图谱总览 | 聚合层、焦点层、列表入口 | 不通过缩小文字展示全部信息 |
| 悬停操作 | 显式按钮、选中态或长按辅助 | 核心功能不得依赖 hover |
| 模态弹窗 | 宽屏弹窗、手机全屏页或底部抽屉 | 软键盘出现时操作按钮仍可达 |

## 6. 资料编辑页面

### 6.1 任务模型

资料编辑包含五类任务：选择资料、阅读原文、查看 OCR、管理页面、查看或审核 RAG 结果。它们共享同一份资料和页码状态，但不要求在手机上同时出现。

### 6.2 Compact

1. 进入资料库时先显示资料列表；选择资料后进入阅读工作面。
2. 阅读工作面顶部显示返回资料列表、资料名、当前页码和更多操作。
3. `PDF 原文` 与 `OCR 识别` 是两个并列模式，切换时保留当前页码。
4. PDF/OCR 占据扣除应用栏和阅读工具栏后的全部可用高度，不能被永久资料列表挤压。
5. 页面列表、资料概览、RAG 和审核从底部抽屉或全屏详情进入。
6. 页面跳转保留已渲染内容，在目标页准备好后替换，显示轻量进度而不是白屏。
7. 排除页、已解析页和待解析页必须有文字或图标状态，不只依赖颜色。

### 6.3 Medium

- 资料列表可以是可关闭侧栏或临时覆盖层。
- 主阅读区始终优先；详情默认按需覆盖，不永久压缩阅读宽度。
- 横屏高度不足时使用与 Compact 相同的工具栏压缩策略。

### 6.4 Wide / Extra Wide

- 可使用资料列表 + 阅读区 + 详情区。
- 详情区可收起，PDF 阅读区设定合理最小宽度。
- Extra Wide 增加辅助上下文，不放大 PDF 之外的空白或无限拉宽 OCR 正文。

### 6.5 状态连续性

以下状态必须独立保存并在尺寸切换后恢复：

- 当前资料；
- PDF/OCR 模式；
- 当前页码与阅读位置；
- 详情标签页；
- 页面包含/排除状态；
- 解析和审核进度。

## 7. 知识图谱页面

### 7.1 任务模型

图谱的目的不是一次展示所有节点，而是帮助教师定位知识、理解上下级关系并进入详情。全图总览只是辅助能力。

### 7.2 Compact

- 默认聚焦当前板块、搜索结果或最近访问节点，不自动把整张图缩进屏幕。
- 搜索/索引作为主要入口，图谱作为探索入口。
- 节点详情在底部抽屉或全屏详情中显示。
- 默认隐藏 MiniMap；通过“全图概览”操作按需打开。
- 工具栏采用 44px 触控区域，文字标签优先于难以理解的图标。

### 7.3 语义缩放

- 低缩放：只显示板块、聚合关系和数量。
- 中缩放：显示主题及主要关系。
- 高缩放：显示知识点名称、标签和操作。
- 缩放时减少信息层级，不能把完整节点和 9px 文字一起缩小。
- 自动定位某个节点时使用可阅读缩放级别；“适应全图”是显式操作，不是移动端默认状态。

### 7.4 列表兜底

图谱中的任何知识点必须能通过可搜索、可分层、键盘和屏幕阅读器可达的列表访问。图谱不是唯一入口。

## 8. 数据密集页面

- 表头排序按钮必须有方向和可访问名称。
- Compact 默认显示完成任务所需的优先字段，其余字段进入展开区或详情页。
- 横向滚动只用于必须逐列比较的数据，并冻结关键识别列。
- 批量选择后出现上下文操作栏，离开前明确保留或取消选择。
- 筛选条件收起时显示激活数量，避免教师忘记列表处于筛选状态。

## 9. 反馈、加载与错误

- 完成、删除、归档、排除是不同状态，不得以“从界面消失”代替状态反馈。
- 预计超过 1 秒的操作显示进行状态；多阶段任务显示当前阶段和阶段耗时。
- 加载占位应保持布局稳定；已有内容在刷新时尽量保留。
- 局部失败只隔离对应资料、页面或任务，不阻塞其他可用区域。
- 错误信息说明发生了什么、影响范围和下一步；提供安全重试或返回入口。

## 10. 可访问性与输入方式

- 支持键盘、触摸和指针，不把 hover 当成唯一入口。
- 焦点状态清晰，抽屉/弹窗关闭后焦点回到触发按钮。
- 状态和风险不只靠颜色表达。
- 图标按钮具有可访问名称，图片和图表提供替代信息。
- 支持系统字体放大、减少动态效果和明暗主题。

## 11. 验收矩阵

每次涉及布局或复杂组件的修改至少验证：

| 尺寸 | 重点 |
| --- | --- |
| 375 × 812 | 最窄手机、阅读区、抽屉、软键盘 |
| 390 × 844 | 常见手机基线 |
| 430 × 932 | 大屏手机、信息密度 |
| 844 × 390 | 手机横屏和低高度 |
| 768 × 1024 | 平板竖屏 |
| 1024 × 768 | 平板横屏/小窗口 |
| 1440 × 900 | 桌面工作台 |

同时检查：

- 页面和容器是否产生意外横向滚动；
- 主要任务能否只用触摸完成；
- PDF/OCR 是否获得稳定阅读高度；
- 图谱初始文字是否可读；
- 抽屉、弹窗和软键盘是否遮挡主要操作；
- 尺寸切换后当前对象、页码、选择和筛选是否保留；
- 200% 缩放和系统字体放大后是否仍可操作；
- 加载、空状态、错误、离线/断线和长内容是否稳定。

## 12. 实施顺序

1. 建立页面壳层、动态高度、字体和触控底线。
2. 改造资料编辑，先完成手机端选择资料 → 阅读 → 页面/RAG 详情闭环。
3. 改造知识图谱的初始焦点、语义缩放和列表入口。
4. 统一表格、工具栏、抽屉、弹窗和批量操作模式。
5. 按业务模块逐页迁移，删除被替代的固定尺寸补丁。
6. 将验收矩阵纳入后续页面完成定义。

禁止以全局缩放、隐藏关键功能、无条件横向滚动或继续叠加固定高度作为短期修复。

## 13. 完成定义

一个页面只有同时满足以下条件才算完成适配：

- Compact、Medium、Wide 下主要任务均可完成；
- 信息层级随空间变化，而不是整体缩小；
- 当前业务状态跨尺寸连续；
- 字体、触控、滚动和软键盘满足底线；
- 加载、空状态和失败状态已验证；
- 通过第 11 节对应尺寸检查；
- 没有为了手机端破坏桌面批量工作的效率。
