# AI 批改协作经验总结

## 1. 第一性原理

AI 批改的最终目标不是识别文字，也不是展示一个看起来完整的流程，而是：

> 基于可追溯的学生作答证据，稳定地产生可复核、可纠正、可确认的最终分数。

由此可以推出五个不可省略的系统要素：

1. **事实源**：学生原始答卷、题目、参考答案和教师确认的评分依据。
2. **观测过程**：文件解析、页面渲染、OCR、题目定位和视觉复核。
3. **判断过程**：依据采分点对学生答案评分，而不是让模型自由发挥。
4. **控制权**：教师能修正识别、调整分数、确认结果和暂停自动流程。
5. **反馈回路**：教师修正必须保存原因和前后结果，用于当前任务校准和后续系统改进。

原图是最高层事实证据。PaddleOCR 提供主要文字和位置证据，视觉模型负责补充观察、冲突复核和语义评分，教师拥有最终裁定权。任何模型输出都不能反向篡改原始证据。

## 2. 不从表象修问题

一次错误通常不是一个孤立问题。例如“某题 OCR 识别错了”，可能继续追溯为：

`文字错误 -> 题目文本串位 -> OCR 块合并 -> 切片区域与文本块不一致 -> 错误证据进入评分 -> AI 产生貌似合理的幻觉`

因此排查顺序应固定为：

`原文件 -> 页面图像 -> OCR 原始块及坐标 -> 题目区域 -> 当前题答案文本 -> 评分依据 -> 模型评分 -> 最终结果`

只有找到最早出现偏差的一层，修复才可能泛化。后层增加提示、兜底或样本特例，只会掩盖错误并积累复杂度。

本轮第 9 题问题就是典型案例：截图区域多数正确，但 Paddle 将相邻题合并成一个文本块，系统又把与截图相交的整块文本当成当前题答案。最终修复规则不是“特殊处理第 9 题”，而是：

- OCR 文本明确以其他题号开头时，不得附着到视觉定位的当前题。
- 没有印刷题号的纯手写答案块仍然可以使用。
- 证据选择规则变化后提升识别管线版本，让旧缓存自动失效。

## 3. 输入格式与解析边界

未来输入可能是 DOCX、纯文本、图片或 PDF，不能围绕某份样本设计系统。

### DOCX 和纯文本

- 优先读取原生文本和结构，不应先转成 PDF 再 OCR。
- 内嵌图片应作为视觉资源保留，但 `image.wmf` 等内部文件名不应直接暴露给教师。
- 题目与参考答案必须分别保留来源证据，不能只展示题目原文。

### PDF 和图片

- 先渲染为页面图像，再进行 OCR 和题目定位。
- PaddleOCR 的文字可能有错，但文本块坐标通常很有价值。
- 题目切片允许与相邻题少量重叠，首要目标是当前题内容完整。
- 坐标只负责定位证据，不能被误当成正确答案。

### OCR 与视觉模型

- PaddleOCR 是主要文字先验，视觉模型不应在没有先验时自由猜测。
- Paddle 文本与题目截图应一起交给视觉模型。
- 两路结果有差异时，系统应展示差异并给出暂定评分，而不是直接拒绝评分。
- 划掉内容、补写文字、填涂选择题必须由图像证据判断，纯文本 OCR 不足以独立裁定。
- 选择题可以是字母，也可以是答题卡填涂，不需要建立过度复杂的专用流程。

## 4. 证据与幻觉控制

幻觉不只是模型问题，也可能由错误输入和系统拼接造成。控制幻觉需要同时约束数据、模型和界面。

### 数据层

- 保存原始 OCR、教师修正文本、视觉复核文本和最终采用文本。
- 不允许评分结果反向补全学生没有写的字。
- 不允许相邻题 OCR 文本进入当前题评分。
- 每次识别规则变化都必须更新管线版本，避免旧缓存伪装成新结果。

### 模型层

- 提示模型只描述图中可见内容，不依据标准答案补全学生作答。
- Paddle 作为主要文字依据，视觉结果用于复核错字、划线、填涂和版面关系。
- 即使两路识别冲突，也先给出可解释的暂定分数和置信度。
- 评分依据不足时才允许返回待定，并明确缺少什么依据。

### 界面层

- 教师必须能同时看到截图、Paddle 结果、视觉复核和评分理由。
- 明确标记当前主识别来源，避免把两路结果混成一个看不懂的文本。
- 教师修正 OCR 后，只重新评分当前学生的当前题。
- 多个学生的修正应并行，后端写回前重新读取最新结果，防止旧快照覆盖其他人的修改。

## 5. 评分依据与试批

评分依据必须先由教师确认，AI 才能批改。采分点不是装饰性说明，而是评分控制参数。

- 标准答案、采分点、分值和教师细则必须可编辑并有明确的保存、取消反馈。
- 采分点默认逐条展示“内容 + 分值”，通过标题右侧编辑按钮统一进入编辑状态。
- 教师亲自批改的试批结果直接成为该生该题最终结果，同时作为本题校准锚点。
- 教师确认 AI 结果也是最终结果，但普通试批确认不属于异常复核记录。
- 评分依据修改后，是否重新试批必须由教师明确触发，不能悄悄覆盖教师终评。

试批的目标不是做一个演示，而是用少量真实样本校准本次任务的评分控制参数，再决定后续自动化程度。

## 6. 批量批改与异常复核

批量批改的核心输出是每位学生每道题的最终分数。异常复核是批量批改内部的纠偏环节，不是与任务平级的独立产品。

### 三种批改方式

- **每份都确认**：教师确认当前学生整份结果后进入下一份。
- **分批确认**：教师检查当前批次后统一确认无异常答卷。
- **自动继续**：正常答卷自动形成结果，真正异常进入复核。

批量页应使用左侧学生列表和顶部题目标签，减少下拉框操作。学生状态必须明确区分：待确认、已确认、有异常。有异常的答卷不能被整份确认绕过。

### 异常进入条件

只有可能影响最终得分的问题才进入异常复核：

- 答卷范围缺失、错误或不完整。
- Paddle 与视觉复核存在实质差异。
- 划掉内容或填涂状态不明确。
- 评分置信度低。
- 评分依据不足，无法给出可靠分数。
- 模型处理失败或输出不完整。

### 每张异常卡片的任务

异常卡片本身就要体现“完成批改”，而不是只展示风险：

- 显示学生、题号、当前 AI 分数和异常原因。
- 可直接确认当前分数。
- 可进入详情修改识别或修改分数。
- 修改原因非强制，可通过教师易懂的标签快速记录。
- 未处理就继续保留在待复核列表，不使用含义模糊的“忽略”。

反馈标签包括：答卷范围不完整、识别文字有误、划掉内容判断错误、采分点遗漏、采分点判断错误、评分过高、评分过低和其他。

## 7. 工程控制回路

完整批改流程是一个闭环控制系统：

`上传材料 -> 解析与观测 -> 教师确认评分依据 -> 试批校准 -> 批量批改 -> 异常隔离 -> 教师纠偏 -> 结果诊断 -> 反馈沉淀`

关键状态必须可观测：

- 材料解析进度和失败原因。
- OCR 与视觉识别来源、置信度和冲突。
- 每道题采用的评分依据版本。
- AI 原分、教师最终分和修改原因。
- 批次已处理、已确认、失败和待复核数量。
- 哪些结果是教师锚点，哪些由 AI 自动完成。

局部异常应隔离，不能阻塞整批；系统性偏差应暂停批改并回到评分依据或识别规则重新校准。

## 8. 产品与工程协作教训

### 修改前

- 先说明原始问题、目标、事实、假设和未决问题。
- 给出最短实现路径、修改范围、风险和验收标准。
- 获得明确同意后再写文件。
- 每轮较大修改前保留 Git 回滚点。

### 修改中

- 不维护 AI 批改专用的学生 mockData，班级与学生以权威名册 API 为准。
- 不针对某个学生、某道题或某份文件写特例。
- 优先减少状态和分支，而不是不断添加“兜底”。
- 修改范围扩大时停止并重新确认，不擅自改变既有 UI 和产品结构。

### 修改后

- 编译和单元测试只是最低要求。
- 必须检查真实 OCR 返回、真实截图、真实保存结果和浏览器完整流程。
- 视觉功能要逐个查看代表样本，不能只相信坐标或接口状态。
- 发现回归时先定位数据源，不用新的提示文字掩盖功能错误。

本轮多次返工的主要原因，是早期过快围绕当前页面和单个现象修改，没有持续沿数据链追到最早偏差。后续应把“先查数据源和状态转换，再改 UI”作为固定纪律。

## 9. 已完成的真实能力

- DOCX 题目与参考答案原生解析和 AI 拆题。
- 学生 PDF/图片上传、权威名册匹配与缺交比对。
- PaddleOCR-VL 解析边界和 OpenAI 兼容视觉模型适配器。
- 题目切片、OCR 主证据、视觉复核和来源图查看。
- 标准答案、采分点和教师细则编辑。
- 真实试批、教师确认、OCR 修正重评和校准锚点。
- 批量批改、三种确认模式、异常分类和教师最终裁定。
- 班级结果诊断和典型问题汇总。
- 管线版本、异常原因、复核决定和反馈标签的数据结构。

## 10. 当前边界与下一步

当前流程已经形成真实闭环，但仍需继续验证稳定性，而不是立即增加更多界面。

下午继续时建议按以下顺序：

1. 用识别管线 V6 重新跑真实答卷，重点复核第 9 题和其他跨题文本块。
2. 完整走一遍“试批确认 -> 批量批改 -> 异常逐项处理 -> 结果诊断”，核对最终分数是否一致。
3. 检查异常直接确认、修改分数和修正 OCR 后，待复核数量、已处理列表和诊断结果是否同步更新。
4. 验证每份确认、分批确认和自动继续三种模式的真实状态转换。
5. 再决定是否优化处理速度、并发数量和视觉预处理，不先增加未经验证的复杂策略。

后续所有新能力都应回到同一个判断标准：它是否让批改证据更可信、评分更稳定、教师更容易发现并纠正错误。
