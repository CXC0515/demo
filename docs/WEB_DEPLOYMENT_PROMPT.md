- 环境变量只使用 `/Users/cxc/Projects/DEMO/.env`；不得提交、打印或在文档中泄露值。
- 母文件夹 `/Users/cxc/Projects/DEMO/var` 是当前权威本地数据。任何迁移先用 SQLite 在线备份和文件快照制作可恢复副本，不得直接覆盖或拿真实唯一副本试错。
- 产品术语使用“母文件夹”“母级规则”“母上下文”“主要母节点”“母子关系”，不要改成“父节点”。

## 原始目标

让一位教师能通过浏览器安全使用当前完整功能，并保证班级、学生、课表、日程、资料、OCR 结果、知识结构和批改记录在部署、重启、升级后不丢失且可以恢复。桌面和手机使用同一个响应式产品，不建立两套独立应用。

当前主要矛盾不是选择最流行的云平台，而是建立以下闭环：

`安全访问 → 正常操作 → 数据持久化 → 任务可观测 → 失败可恢复 → 备份可验证`

## 第一步：只读调查

先用真实代码和运行结果回答，不凭印象：

1. 当前前端、API、数据库、上传文件、解析产物和 OCR/AI 外部依赖的边界是什么？
2. `npm run build` 产物如何被服务？生产环境是否能同源访问 `/api` 与 `/uploads`？
3. 所有可写路径、最大上传体积、最长任务耗时、进程重启行为和平台超时要求是什么？
4. 当前是否存在登录、会话、权限、CSRF/CORS、速率限制、日志脱敏和资料下载授权？
5. 本地 PaddleOCR/Python/PDF 工具哪些是运行必需，哪些可以由远程服务替代？
6. 目标平台是否支持长期运行的 Node 进程、持久磁盘、HTTPS、自定义域名、备份和所需 CPU/内存？
7. 母文件夹数据怎样以副本迁移、怎样校验、怎样回滚、怎样恢复？

先运行不修改数据的检查，并记录证据。不要因为 UI 能打开就判断部署完成。

## 必须向用户确认的产品与运维决策

调查后先向用户确认：

- 部署平台或可接受的平台范围；
- 是否已有域名；
- 仅本人使用、受邀教师使用，还是计划公开注册；
- 可接受的月度预算和停机时间；
- 学生数据允许存放的地区及合规要求；
- 是否必须保留本地 OCR，还是允许全部使用远程 OCR；
- 首次上线是否接受单实例，以及期望的备份频率和恢复目标。

这些答案会改变身份系统、数据架构、平台和迁移方式。未确认前只提交方案，不擅自选择并绑定供应商。

## 推荐的第一阶段方案

除非调查得到相反证据，优先方案是：

1. 一个长期运行的 Node/Express 实例，同源托管 Vite 构建产物、`/api` 和受鉴权保护的资料访问。
2. SQLite、上传资料、分页图片、解析产物和备份目录放在同一持久卷的明确目录下；路径通过环境变量配置。
3. 增加生产启动脚本、启动配置校验、数据库迁移/备份、优雅退出、结构化日志、存活检查和就绪检查。
4. 上线前加入 HTTPS 和可靠的单用户登录或平台访问门禁；未建立权限边界前，不公开学生与教学数据。
5. 明确代理层的请求体、上传、长任务和空闲超时；OCR 请求改为可查询状态的异步任务，查看资料不被解析阻塞。
6. 使用母文件夹数据的在线备份副本做迁移演练，核对数据库完整性、关键表数量、文件存在性和端到端读取，再决定切换。
7. 对关键路径做桌面与手机真机尺寸烟雾测试，但保持同一数据模型和同一功能语义。

第一阶段不要直接把 SQLite 改成 PostgreSQL，也不要为了横向扩容先引入复杂微服务。只有在多人并发、跨实例运行或协作需求被真实验证后，再提出第二阶段：PostgreSQL、对象存储、持久任务队列、租户隔离和审计日志。

## 验收标准

- 使用生产命令启动一个入口即可访问完整网页，前端、API 和资料访问同源工作。
- 未登录用户无法访问学生信息、上传资料、OCR 结果和 API。
- 服务重启后数据库、上传资料、OCR 页面、知识节点和任务状态仍可用。
- OCR/AI 长任务有明确状态、失败信息和重试/人工接管方式，不阻塞 PDF 查看。
- 健康检查区分进程存活、数据库/持久卷就绪和外部 AI 配置状态。
- 完成一次从备份恢复到临时目录的演练，并用完整性、表数量、文件引用和 UI 烟雾测试验证。
- 桌面和常见手机宽度完成核心流程测试，没有独立分叉的手机版业务逻辑。
- `.env` 和密钥没有进入 Git、构建产物、浏览器变量、日志或错误响应。
- 所有变更通过类型检查、相关测试、生产构建和端到端烟雾验证，并记录真实结果。

最终交付应包括：部署架构与决策记录、可复现部署配置、环境变量模板、备份/恢复手册、数据迁移记录、验证证据和仍未解决的风险。未经单独授权，不要推送、开 PR 或合并。
